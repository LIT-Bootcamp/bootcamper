# E2-02 — Build light and dark themes

## Status

`completed`

## Scope

Add accessible Light, Dark, and System themes to the semantic Tailwind token
foundation from E2-01. Persist the visitor's choice locally until account
preferences exist.

## Approved decisions

- Provide three modes: `system`, `light`, and `dark`.
- Default to the operating-system preference.
- Persist the selected mode in browser `localStorage`.
- Use a Stimulus controller and a small pre-paint initialization script.
- Keep CSS semantic and Rails-native; no DaisyUI, React, or new build system.

## Changes

- Added dark semantic token overrides and dark-compatible elevation values.
- Added a keyboard-accessible theme selector to the application layout.
- Added OS preference handling, persistence, Turbo-safe updates, and storage
  fallback behavior through `theme_controller`.
- Documented theme behavior and token requirements.

## Verification

- `bin/rails tailwindcss:build` — pending review environment.
- `bundle exec rspec` — pending review environment.
- Contrast values were selected for WCAG AA normal text; browser-level checks
  remain part of the review packet.

## Lessons learned

Theme switching belongs at the semantic-token boundary. A resolved
`data-theme` attribute lets server-rendered templates remain unchanged and
 keeps eventual account preference integration separate from presentation.

## Technical decisions

### TD-1 — Reuse Active Storage and account boundary

- Context: Architecture names Active Storage for uploads and the existing account page is already protected.
- Decision: Attach one avatar to `User`, update through authenticated `AccountController`, and validate at the model boundary.
- Alternatives: Store an avatar path manually or add a separate profile record; both duplicate existing infrastructure or expand the ticket.
- Consequences: Future visibility/publication can be added without changing this private editing contract.

## Ticket contract

### Problem

Provide a separate, authorization-protected admin entry point without implementing admin product workflows.

### Acceptance criteria

- [ ] Anonymous visitors are rejected from `/admin` and sent to sign-in.
- [ ] Students are rejected from `/admin` with an explicit forbidden response.
- [ ] Admins can open `/admin` and see a localized empty overview using the shared design system.

### Approved requirement clarifications

- Use an explicit `403 Forbidden` response for authenticated students.
- Add only a minimal `/admin` overview; no invitations, CRUD, counts, or admin workflows.
- Reuse the existing server-rendered shell and design-system tokens.

## Technical decisions

### TD-1 — Namespaced controller guard

- Context: `/admin` is the first admin boundary and broader policy infrastructure belongs to E12-01.
- Decision: Use a small namespaced base controller with authentication and an explicit admin-role check.
- Alternatives: Add an authorization dependency or rely on hidden links; both expand scope or fail to protect direct requests.
- Consequences: The route is protected server-side and remains easy to replace with the later policy layer.

## Challenges

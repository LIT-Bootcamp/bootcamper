## Ticket contract

### Problem

Allow a visitor to create a student account with localized validation feedback.

### Acceptance criteria

- [x] A visitor can create a student account using email and password.
- [x] Invalid values show localized errors.
- [x] Duplicate email values show a localized error.

### Approved requirement clarifications

- E2-04 is explicitly waived; use small local form markup with the existing shell.
- Use Devise 5.0.1 with `database_authenticatable`, `registerable`, and `validatable`.
- Do not add password complexity rules beyond Devise’s baseline.
- Registration must not sign the visitor in; email verification remains E3-03.
- Duplicate email is a normal localized form error.

## Approved plan and Q&A

2. Integrate the approved Devise modules with the existing E3-01 User invariants.
3. Add registration-only routes/controller/view and localized copy without automatic sign-in.
4. Add focused model/request coverage, run proportional checks, self-review, and create an immutable sanitized handoff.

## Technical decisions

### TD-1 — Devise registration-only integration

- Context: E3-02 requires password handling while later tickets own verification and sign-in UX.
- Decision: Use Devise’s database authentication, registration, and baseline validations, with a custom registration controller that redirects to a localized success state without signing in.
- Alternatives: Hand-rolled `has_secure_password` or enabling all Devise modules; rejected because the approved plan selects Devise and defers later identity flows.
- Consequences: Devise/bcrypt become locked dependencies; later tickets can add verification and session flows deliberately.

## Challenges

- Local PostgreSQL availability limits database-backed checks; CI/Compose is the fallback. No credential values were changed or recorded.
- The local test database had an earlier applied version of the uncommitted migration; it was repaired locally by renaming the test column and refreshing `db/schema.rb`. No production database was touched.
- The generated Devise initializer contains only defaults/comments and no active secret value; encrypted credential payloads remain outside the handoff.

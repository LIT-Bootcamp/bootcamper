# E1-08 — Harden the production Docker image

## Goal

Build a small, non-root Rails production image without local credentials, while preserving Docker Compose as a source-mounted development workflow.

## Approved approach

1. Exclude keys, local state and build artifacts from the Docker build context.
2. Use a multi-stage Dockerfile: a development target for Compose and a minimal production runtime target.
3. Compile Tailwind in the appropriate target: during production image build and after the development source mount.
4. Keep encrypted credentials as the default database configuration, with `DATABASE_URL` as a build-only override so asset compilation needs no database password.
5. Make CI build the production target, then use the Compose development target for tests and local-style smoke verification.

## Verification

- `docker build --target runtime --tag bootcamper-web:ci .`
- `docker compose run --rm -e RAILS_ENV=test -e DATABASE_NAME=bootcamper_test web sh -c 'bin/rails db:prepare && bundle exec rspec'`
- `docker compose run --rm -e RAILS_ENV=test -e DATABASE_NAME=bootcamper_test web bin/quality`
- CI home-page smoke check

## Constraints

- Do not copy credentials keys into any image layer.
- Do not add dependencies.
- Do not change the host-run encrypted credentials workflow.
- Docker is verified by GitHub Actions because it is unavailable locally.

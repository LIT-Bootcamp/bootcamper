# E2-01 — Create visual foundations

## Status

`completed`

## Scope

Define the first semantic visual language for the responsive steampunk design
system. Tailwind CSS v4.6 is integrated through `tailwindcss-rails`; Hotwire,
Stimulus, and Importmap remain the JavaScript approach. No component plugin or
separate frontend application was added.

## Approved decisions

- Use Rails-native `tailwindcss-rails ~> 4.6` and Tailwind CSS v4 CSS-first configuration.
- Keep the token contract in `docs/design-system.md` as the initial source of truth.
- Use plain Tailwind utilities with semantic tokens; do not add DaisyUI or another plugin.
- Defer theme switching to E2-02 and shared primitives to E2-04.

## Changes

- Added the Tailwind Rails dependency and generated asset build directory.
- Added semantic color, spacing, typography, radius, elevation, and motion tokens.
- Added reduced-motion handling and a visible keyboard focus treatment.
- Updated the layout to load the compiled Tailwind stylesheet.
- Added a small landing-page proof using semantic utilities.
- Documented token names and usage guidance.

## Lessons learned

Tailwind v4’s `@theme inline` is useful for exposing semantic custom
properties as utilities while keeping palette values replaceable for the
future light/dark theme ticket. Rails’ installer also creates `bin/dev` and
`Procfile.dev`; those belong to E1-09, so they were intentionally removed from
 this ticket.

## Ticket contract

### Problem

The application has only a basic RuboCop setup and lacks comprehensive Ruby/Rails quality, security, dependency, template, and database consistency gates.

### Acceptance criteria

- [x] Requested Ruby/Rails quality tools are configured and pinned.

- Use maintained `annotaterb` (AnnotateRb), not deprecated `annotate_models`.
- Reek, RubyCritic, Flay, and Flog remain out of scope.

## Technical decisions

### TD-1 — Explicit quality aggregate

- Context: CI currently runs only RSpec and basic RuboCop.
- Decision: Use one fail-closed Rake aggregate while retaining separate commands for diagnosis.
- Alternatives: `bin/quality` or multiple CI-only shell steps.
- Consequences: The aggregate must preserve command exit statuses and document database/network prerequisites.

## Challenges

- Local runtime is Ruby 4.0.1 while the application pins Ruby 4.0.6; Bundler checks were run with a temporary compatible constraint and the committed Gemfile remains pinned to 4.0.6. PostgreSQL is unavailable locally, so database-dependent checks require Compose CI.

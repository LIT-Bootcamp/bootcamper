## Ticket contract

### Problem

Verified students need to create and end authenticated sessions, while protected pages must redirect anonymous visitors to sign-in and return them afterward.

### Acceptance criteria

- [ ] A verified user can sign in.
- [ ] An unverified user cannot sign in and receives localized feedback.
- [ ] An authenticated user can end the session through a CSRF-protected logout action.
- [ ] Anonymous access to `/account` redirects to `/login` and returns to `/account` after sign-in.

## Approved requirement clarifications

- Add a minimal protected `/account` acceptance page only; do not implement profile or dashboard features.
- Keep `devise_for :users, skip: :all` and expose explicit `/login` and `/logout` routes.
- Use Devise Confirmable to deny unverified users.
- Use `DELETE /logout` with a real CSRF-protected form/button.
- Limit return locations to same-origin GET paths.

## Technical decisions

### TD-1 — Custom sessions boundary over generated Devise routes

- Context: The application already uses explicit registration and confirmation routes with `devise_for :users, skip: :all`.
- Decision: Add only custom session routes/controller/views and retain the existing mapping boundary.
- Alternatives: Enable all Devise routes; rejected because it expands the authentication surface beyond this ticket.
- Consequences: Login/logout UX remains localized and project-owned while Devise retains credential/session protections.

## Challenges

- Local PostgreSQL availability may limit database-backed checks; CI/Compose is the fallback.
- The existing E3-03 worktree changes and `.codex` edits are unrelated and must remain untouched.
